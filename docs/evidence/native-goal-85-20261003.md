# Owner's aspirational 85% goal: separate measurements

Owner direction, 2026-10-03: aim for 85% native/matched coverage and carry
verified matches into the port. This is a continuing target, not a deadline or
permission to inflate the scope or count assembly/data as recovered C.

## Baseline

| Measurement | Verified value and limit |
|---|---|
| (a) Matched C functions | **2,704 / 4,464 = 60.57%**; objdiff source `4234d0f6`, all pinned ROM hashes pass |
| Supporting matched code-byte measure | **388,028 / 1,383,684 = 28.04%** |
| (b) Production native runtime with interpreter disabled | **3,000-frame field diagnostic smoke PASS; no accepted useful playable slice yet; percentage unknown** |
| (c) Matched bodies integrated and tested in the port | **102 verified matched-source battle bodies**, a bounded subset; whole-port total unknown. Each is linked from its expected host object and has completed differential comparisons at O0/O2/UBSan |

The earlier README count, 2,651, was stale. These 53 additional reported matches
already existed at the checkpoint; none was newly authored during this census.
The denominator remains 4,464. Its 85% threshold is 3,795: **1,091 additional
verified matches** are needed. The function and byte percentages describe
different things; an abundance of short leaves must not hide large missing
gameplay routines.

The report covers ten pinned build targets and includes the SDK category inside
the main-executable category. SDK counts do not constitute native game-engine
coverage. Code inside other disc archives, including RESULTS and intro modules,
is not in this report's denominator. Whole-game coverage remains unmeasured;
any future scope expansion must identify new retail functions explicitly and
retain the original baseline alongside it.

## Next bounded milestones

1. Finish the census and correlate matched functions with actual linked object
   ownership and per-function test evidence. Distinguish linked candidates,
   port overrides and exercised/proven bodies. Keep each raw manifest.
2. Gate a fail-closed interpreter-disabled mode in the production adapter.
   Validate normal behavior with the existing suite, then run the field smoke
   route with the mode enabled. A diagnostic smoke is not full playable-slice
   acceptance; meaningful input, state/visual/audio/timing/save evidence follow.
3. Repair and isolate the RESULTS route driver, then compare repeated reference
   runs against native adoption at results entry, equal render boundaries and
   return. Preserve the empty-party fixture's limitations and establish a valid
   gameplay fixture before claiming victory or broader native execution.
4. Convert the next RESULTS caller only after guest-frame and call-sequence
   recording are proven. `801E3A18` is a bounded candidate whose six helper
   leaves are now differential-tested. Matching adoption requires independent
   pinned ROM/objdiff proof; semantic reconstruction alone does not count.

The port remains hybrid: roughly 48 RESULTS routines, intro, and other battle
paths still interpret. Menu/shop guest versus host structure layout, callback
and random-state contracts, valid progression fixtures and incomplete test
cases are significant blockers. Nineteen baseline binary retail-data runs
(25,068 bytes) remain a release blocker. No private package is promoted from a
failed gate; public release remains prohibited.

## Forecast

The census is one small runner cycle; reliable route/dispatch evidence should
be budgeted in several bounded cycles rather than assumed to pass first try.
There is no measured sustained matching/conversion rate yet, so a date for 85%
would be invented. At 1,091 remaining matches and substantially less code-byte
coverage, weeks to months of continued matching and runtime work is a plausible
planning scale, with the larger callers capable of extending it. Production
85% native coverage is harder to forecast and cannot be derived from function
counts. Re-estimate after several gated batches using actual verified gains,
time spent, scope and remaining blockers. Continue through milestones without
closing the project at each small checkpoint.
