## How to read this

Progress is **matched bytes against the retail target**, the measure
objdiff and decomp.dev use. Objects are built with `-DSKIP_ASM`, so a
function still carried as `INCLUDE_ASM` contributes its full size to the
denominator and **nothing** to the numerator. This is deliberately a
harsher bar than "the ROM rebuilds byte-identically" -- that is true of
several overlays already and says nothing about how much C exists.

## Coverage holes — code this report does NOT measure

`objdiff` only sees modules the build system builds. Anything missing
from `gears.toml`'s `overlays` list is absent from both the numerator
**and the denominator**, so the headline above is not a fraction of the
whole game.

Also check `config/checksum.sha`, which is the byte-exactness gate: it
must list every module you intend to match. A module that is built but
absent from that file is never checked.

## Regenerating

```
make report                                      # builds + writes build/progress.json
python3 tools/scripts/progress_dashboard.py      # rewrites this file
```

`make report` runs `gears report`, which passes `-DSKIP_ASM` and skips
linking, so the currently-red slus link does not block it.
