# Retail field lighting initialization correction

The natural Lahan run reached the world map, but its aftermath screenshots showed saturated blue Gear surfaces. This prompted review of the known light-initialization concern. The prior claim that retail also reads an unwritten ninth argument was incorrect: original instructions at 8007164C and 80071678 explicitly store zero at sp+0x24, in each call delay slot. The complete 100-byte caller region 80071618..8007167C was verified against disc/field.bin; SHA256 4446d152910aa56f7191baea4bff586009f361e9c83cc5d92160222b618bd51c.

The old native FieldLoad passed only eight values to a nine-value writer. It also passed zero where retail writes 0x800 to the seventh color-matrix element. The two production calls now supply all nine values. A full prototype checks arity. The writer arguments are now int, matching the six retail LW stack loads rather than the previous unsigned-halfword loads generated for short parameters.

Validation: run `bash pc_port/tests/run_field_light_init_test.sh`. It executes original retail caller and writer instructions without callbacks, compares all 96 surrounding bytes against verbatim production call statements linked to the full production main.c translation unit, and varies 256 initial register/stack/memory patterns. The old body fails at color-matrix element 6. A further 65,536 cases cover every low-halfword value in all nine writer positions with nonzero upper bits. O0, O2 and UBSan pass. Four separately compiled negative controls reject a missing red-light value, nonzero ninth element, wrong direction sign, and wrong destination. This is a bounded caller-region test, not whole FieldLoad execution.

Native and full PSX builds PASS. The complete 64-byte func_80077844 now matches retail exactly, with zero relocations. FieldLoad remains nonmatching: 3416 compiled versus 3484 retail bytes. See exact-status.json, pins.json and change.diff.
