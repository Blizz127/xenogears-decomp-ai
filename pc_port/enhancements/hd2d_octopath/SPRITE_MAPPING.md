# Fei atlas mapping evidence

This document records PORT implementation evidence. No cleanroom sources or retail artwork were copied.

`include/field/actor.h` names SpriteData halfword +0x34 `curSpriteFrame`. `src/slus_006.64/system/work_list.c`, `func_8001D2B0`, sets it to `frameIndex` and queues the sprite for upload. `temp1.c` runtime VM advances or reverses frame indices, and opcode 0xBE selects packed low-nine-bit frame indices; its negative packed form can indirect through a table at +0x60. `animation_scripts.c`, `func_80022660`, likewise seeks and changes frame indices when resynchronizing scripts. Thus +0x34 is selected frame identity, not elapsed time. Dividing it by two or wrapping modulo the authored gait cycle has no demonstrated semantic basis.

`animation_scripts.c`, `func_800223B0`, stores its angle argument at +0x80, selects direction-specific animation tables according to mode bits at +0xA8, and may mirror them through +0xAC. `src/field/main/misc2.c` supplies camera yaw from `g_CamInterpolation+0xA` plus actor angle at ActorData+0x108. The angle is camera relative in the ordinary field path. Legacy Fei presentation quantizes masked angle as right [3584,4096) and [0,512), front [512,1536), back [1536,2560), left [2560,3584). New enum values explicitly follow authored atlas row order FRONT=0, BACK=1, LEFT=2, RIGHT=3. This quantization preserves the legacy presentation convention; it does not prove all retail facing modes share those four sprite silhouettes.

The root-generated atlas uses four rows (front/back/left/right) and four authored columns (idle/left step/passing/right step). `describe_hd2d_cells.py` records cell rectangles from inspected PNG dimensions, including uneven divisibility, and marks `game_mappings` and `approved_opening_maps` empty. This authored-cell manifest deliberately cannot pass the runtime compiler. Review orientations and anchors before producing runtime metadata. Fei idle/walk/run frame IDs require actual package script decoding or an authorized local runtime trace of animation ID, frame index, angle, direction mode, and frame/table identity. Existing generic interpreter tests prove mechanics, not Fei's specific package mapping.

The existing `fei_hd2d.c` path directly replaces player sprite primitives. Separately, `pc_port/src/plat/xg_plat_psycross.c`, `xg_plat_renderer_upload_image`, hashes ORIGINAL PSX upload bytes through `xg_plat_mods_lookup_asset`, and applies same-size w*h*2 binary VRAM replacements. An RGBA atlas cannot be supplied to that hook as a `.bin` replacement. The optional new `XgHd2dAtlasFindSource` only associates canonical SHA-256 plus exact source byte length with validated atlas metadata. It contains no production keys. A future agreed hook must hash original bytes before replacement, associate the upload/frame owner with the selected actor, and select the RGBA atlas during primitive rendering. A hash alone does not establish animation phase, actor identity, map eligibility, or safe replacement readiness.

Renderer uses the existing single default-off `XgHd2dConfig.enabled` for lookup and upload. Empty map approval remains fail closed. Baseline eight-cell Fei behavior remains untouched. No shared hook is installed pending coordinator agreement.
